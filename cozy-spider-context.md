## 1. Что делаем

Браузерный пасьянс «Паук» с упором на визуал и атмосферу.

**Killer feature — уют (cozy).** Не механика (она стандартная и всем известна), а ощущение: красивый стол, живой свет, вес и материальность карт, ламповый саундтрек. Продукт продаётся атмосферой, а не игровым процессом.

**Ключевой принцип, к которому возвращаться при любом споре о приоритетах:**

> Логика пасьянса тривиальна. Вся сложность и вся ценность проекта — в подаче. Порядок вложения сил: **арт → тайминги анимаций → звук → шейдеры.**

Хорошо нарисованная колода с правильными таймингами ощущается уютнее, чем посредственная колода с bloom и DOF.

```

Шейдеры         vite-plugin-glsl (#include + hot reload)

Звук            Web Audio API напрямую (не Howler — нужен свой микшер)
Пайплайн ассетов @assetpack/core
Тесты           Vitest (покрывать core/)
Бэкенд          Node/Bun на VPS в РФ
БД              Postgres (можно self-hosted Supabase)
Хранилище       Selectel S3 / Yandex Object Storage + CDN
Платежи         ЮKassa
```

**Чего осознанно НЕ делаем:**

- ❌ **Godot / Unity / Bevy web export** — 15–30 МБ бандла, медленный старт, флаки на мобильном Safari. Прямо противоречит требованию «грузится везде».
- ❌ **WebAssembly для игровой логики** — не нужен, JS справляется за микросекунды. Единственное оправданное место — солвер (см. §5), и только после замеров.
- ❌ **Cloudflare как CDN** — в РФ работает нестабильно.
- ❌ **Supabase Cloud в EU-регионе** — нарушает локализацию ПД (§9).

## 4. Архитектура

### Слои

```

               GameState, applyMove(), getLegalMoves(), createDeal(seed, suits)
               Детерминированный ГСЧ (mulberry32) → расклад дня, шеринг, тесты

engine/        WebGL-рендер, атласы, планировщик анимаций, ввод
  shaders/     ← шейдеры живут ЗДЕСЬ, это код, а не ассеты
    lib/       noise.glsl, lighting.glsl (общие чанки через #include)
    card.vert  card.frag
    post/      bloom.frag, lut.frag, grain.frag

platform/      PlatformAdapter — единственная точка выхода наружу
  RuAdapter    VK/Yandex OAuth + ЮKassa + свой бэкенд
  LocalAdapter Заглушка для разработки, всё разблокировано

app/           UI-оверлей, настройки, i18n, персистентность

art/           ИСХОДНИКИ (SVG, PSD). Не идут в бандл.
dist-assets/   Билд-артефакты. В .gitignore.
```

### Правило разделения логики и рендера

**Логика не ждёт анимацию.**

Игрок делает ход → состояние в `core` меняется мгновенно → наружу летит семантическое событие (`CardsMoved`, `StackCompleted`, `Dealt`) → рендер подписан и превращает событие в таймлайн анимации, складывая в очередь.

Визуальное состояние — это «догоняющая» интерполяция логического. Без этого разделения вы утонете в колбэках «а что если игрок кликнул, пока летит предыдущая карта».

Побочные выгоды: undo/redo как стек команд, реплеи, сохранение в пару килобайт (сид + список ходов), полное покрытие тестами без пикселей на экране.

### PlatformAdapter

```ts
interface PlatformAdapter {
  init(): Promise<void>
  getUser(): Promise<User | null>
  signIn(provider: 'vk' | 'yandex' | 'telegram' | 'email'): Promise<User>
```

## 5. Графика (WebGL)

### Что даёт WebGL, чего не даст Canvas2D

**Нормал-мэппинг на картах.** Карта — квад с картой нормалей (бумажное зерно, тиснёная рамка) и spec-маской. Свет от лампы реально играет по поверхности при подъёме карты. Единственный эффект, ради которого стоит весь WebGL: подсознательно читается как «физический объект».

**Изгиб карты в вершинном шейдере.** Квад разбит на сетку 8×12. Карта провисает при перетаскивании, прогибается от скорости при раздаче, выгибается при перевороте. Самый дешёвый способ добавить объекту вес.

**Мягкие тени без shadow map.** Квад с радиальным градиентом под картой, смещённый по вектору от источника света. Радиус размытия ∝ «высоте» карты над столом. Поднял — тень отъехала и размылась.

**Переворот карты.** Перспективная матрица в вершинном шейдере, back-face по знаку нормали для подмены текстуры, плюс изгиб в середине анимации.

### Постобработка (ping-pong между FBO)

1. Bright pass → downsample → blur → **bloom** (в ¼ разрешения!)
2. **Фейковый DOF** — сила блюра как функция расстояния до активной колонки
3. **Виньетка** с тёплым оттенком
4. **Хроматическая аберрация** — доли пикселя на краях
5. **3D LUT** ← главный инструмент, см. ниже
6. **Зерно + текстура бумаги**, анимированные

**LUT — лучшее соотношение «атмосфера на килобайт».** Куб 32×32×32, развёрнутый в текстуру 1024×32, весит килобайты и полностью меняет настроение сцены. Сделать 5–6: тёплый вечер, дождь, свечи, зимнее утро, ночь. Это одновременно и арт-инструмент, и товар для платных паков.

### Частицы

Инстансинг, симуляция целиком в вершинном шейдере через per-instance сид и время. CPU не участвует. Пылинки в луче, угли, дождь, листья — тысячи частиц при нулевой нагрузке.

### Дисциплина отрисовки

- Все лица карт в одном атласе → один draw call
- **Вся сцена < 10 draw calls.** Больше — что-то не так с сортировкой по материалам
- WebGL2 (инстансинг, MRT, sRGB) — покрытие ~97%
- `mediump` во фрагментных шейдерах: старые Adreno/Mali имеют проблемный `highp`

### Тиры качества — ОБЯЗАТЕЛЬНЫ

| | Ultra | High | Medium | Low |
|---|---|---|---|---|
| Пост | вся цепочка + DOF | bloom + LUT + зерно | LUT + виньетка | LUT |
| Частицы | 2000 | 500 | 0 | 0 |
| Карты | normal + spec + изгиб | normal + изгиб | плоские | плоские |
| Фон | живой шейдер 60fps | живой шейдер 30fps | запечён | запечён |

**Арт-направление одинаковое на всех тирах.** LUT остаётся везде — он почти бесплатный и несёт большую часть настроения. Деградируют эффекты, а не стиль.

**Определение тира:** замер медианы времени кадра за первые 2 секунды. Не по строке рендерера — её маскируют.

### Оптимизация

- **Render-on-demand.** Пасьянс 95% времени статичен. Рисовать по dirty-флагу. Фоновую атмосферу — на 30 fps, после 10 сек бездействия запекать в статическую текстуру.
- **Клампить DPR:** `Math.min(devicePixelRatio, 2)`
- **Постэффекты в ¼ разрешения** — блюр на нативном это главный убийца среднего Android
- **Ноль аллокаций в кадре** — пул объектов, иначе GC даёт микрофризы
- **Прогрев шейдеров на загрузке** — отрисовать по невидимому квадру каждой программой, иначе фриз при первом подъёме карты

## 6. Ассеты

### Три уровня, не смешивать

| Уровень | Где | В git? |
|---|---|---|
| **Исходники** (SVG, PSD) | `art/` | SVG — да. Растр — Git LFS или вне репо |
| **Билд-артефакты** (атласы, KTX2) | `dist-assets/` | Нет, `.gitignore` |
| **Рантайм** | S3 + CDN | — |

### Композитная колода — ключевое решение

Наивно кажется, что нужно 104 картинки. На деле:

- Уникальных лиц максимум 52; в режиме одной масти — 13
- Числовые карты (2–10) = рамка + процедурно расставленные пипсы
- **Реально иллюстрировать нужно 12 фигурных карт** + рубашку + рамку

Это не эстетика, а выживание: 104 текстуры 512×768 RGBA ≈ 160 МБ VRAM = мгновенный вылет вкладки на iPhone.

### Форматы и ловушки

| Что | Исходник | Рантайм | ⚠️ |
|---|---|---|---|
| Лица, пипсы, рамка | SVG | атлас 2048², KTX2 | |
| Фон стола | PNG 2x | KTX2 (UASTC) | |
| Карты нормалей | PNG lossless | KTX2 **UASTC** | ⚠️ 1 |
| LUT | PNG lossless | PNG как есть | ⚠️ 2 |
| Звук | WAV | Opus в WebM | |
| Шрифты | TTF | WOFF2, subset | ⚠️ 3 |

**⚠️ 1. Нормали нельзя жать с потерями.** WebP lossy и JPEG делают цветовую субдискретизацию, а в нормал-мапе R/G/B — это не цвет, а компоненты вектора. Результат: рябь на освещении, которую полдня ищешь в шейдере.

**⚠️ 2. LUT нельзя жать и нельзя мипмапить.** Сжатие с потерями → полосатость на градиентах. Мипмапы и билинейка поперёк тайлов → перетекание цветов между слоями куба. Загружать с `NEAREST` по X внутри тайла, без мипов, без premultiplied alpha.

**⚠️ 3. Кириллица в шрифтах.** Большинство красивых декоративных шрифтов её не имеют вообще, либо содержат уродливые автоглифы. **Проверять до утверждения типографики.** Смотреть Paratype, Cyreal, Google Fonts с явной поддержкой Cyrillic.

**Общее правило:** для «данных, притворяющихся текстурой» (нормали, LUT, маски) отключать premultiply alpha и sRGB-конверсию. Не смешивать цвет и данные в одном атласе — цвет хочет sRGB и мипы, данные хотят линейное пространство.

### Бюджет VRAM

```
Атлас лиц       2048² ASTC 4x4   ≈ 4 МБ
Атлас нормалей  1024² UASTC      ≈ 1 МБ
Фон             2048×1024 KTX2   ≈ 2 МБ
LUT × 6         1024×32 RGBA     ≈ 0.8 МБ
Частицы, маски                   ≈ 1 МБ
─────────────────────────────────────────
                                 ≈ 9 МБ
```

Цель на мобильных — **суммарно < 40 МБ по текстурам.** Запас огромный.

### Пайплайн

```bash
npm run build:assets   # art/ → dist-assets/  (AssetPack)
npm run build          # vite build, подхватывает манифест
```

Конвенция имён: `{категория}-{имя}-{вариант}.svg`. Без пробелов и кириллицы в путях. AssetPack умеет разбирать теги из имён папок.

> **Завести `art/` и `assetpack.config.js` ДО того, как нарисована вторая карта.** Пайплайн в начале = вечер. Пайплайн на 60 готовых файлов = неделя и испорченное настроение.

### Русская колода

В российской традиции фигурные карты — **В / Д / К / Т** (валет, дама, король, туз), а не J/Q/K/A. Это не строка в i18n, а отдельный набор глифов в атласе. Заложить вариативность атласа по локали с самого начала. Может стать отдельной платной колодой в русском стиле.

### Манифест

```json
{
  "version": 12,
  "packs": {
    "base":    { "public": true,  "files": ["cards-color.a3f9.ktx2"] },
    "candles": { "public": false, "sku": "pack.candles", "files": ["..."] }
  }
}
```

Игра грузит манифест первым, из него понимает бесплатное, по премиуму спрашивает бэкенд.

### Где физически лежит

1. **Бандл Vite** → VPS/S3, статика. Шелл, JS, шейдеры (внутри JS), критичный CSS, шрифты. Content-hash + `Cache-Control: immutable, max-age=31536000`
2. **Публичный бакет + CDN** → бесплатная колода, базовый фон, звуки
3. **Приватный бакет** → платные паки, только по подписанной ссылке с TTL 10 мин

### Кеш

Service Worker + Cache API:
- Бандл и публичные ассеты → cache-first (immutable по хешу)
- Манифест → network-first с фолбэком
- Премиум-паки → в Cache API после скачивания

Со второго запуска игра стартует мгновенно и работает офлайн.

### Прогрессивная загрузка

1. Шелл + загрузочная сцена — инлайн, < 50 КБ
2. Движок + LQIP-атлас (512²) — играть уже можно
3. Полный атлас под текущий DPR — бесшовная подмена
4. Фоны, частицы, звук — в фоне
5. Премиум-паки — по требованию

Цель: первый осмысленный кадр < 2 сек на 4G, стартовый payload < 1.5 МБ.

## 7. Аудио и lo-fi радио

### Внешние стримы — исключено

YouTube в РФ в феврале 2026 перешёл от замедления к полной блокировке (домен убран из НСДИ). Плюс: ретрансляция чужого потока в коммерческом продукте нарушает лицензии, Icecast-станции падают, и нет контроля над кроссфейдом и синхронизацией с настроением сцены.

**Только свой контент.**

### Откуда музыка

| Вариант | Цена | Комментарий |
|---|---|---|
| **Заказать у продюсера** ✅ | $500–2000 за 10–15 треков | Полные права, уникальное звучание. BeatStars, SoundBetter, TG-каналы битмейкеров. В договоре — **полная передача исключительных прав**, не лицензия |
| Epidemic Sound / Artlist | подписка | Узнаваемо стоковое. Проверять, покрывает ли лицензия интерактивные продукты |
| Pixabay / FMA (CC0) | 0 | Для прототипа. Для платного продукта происхождение трудно проверить |
| **Процедурная генерация** | 0 | См. ниже |

### Процедурный lo-fi (Tone.js)

Решает лицензии полностью:

- Сэмплы Rhodes/пианино (12 нот, ~1.5 МБ) + брейк-луп
- Генератор гармонии: ii–V–I со случайными заменами в септаккордовой палитре
- Tape wow/flutter: медленный LFO на `detune`, ±8 центов
- Lowpass ~3.5 кГц + сатурация через WaveShaper
- Sidechain: GainNode, приседающий на каждую долю
- Винил-шум поверх

**Рекомендуемый гибрид:** заказные треки как основа + процедурный слой для эмбиента.

### Четыре слоя

| Слой | Что | Вес | Загрузка |
|---|---|---|---|
| Музыка | треки 2–4 мин | ~2.2 МБ (Opus 96k) | стриминг |
| Эмбиент | дождь, камин, ветер, кафе | 10–30 сек луп, ~300 КБ | сразу в AudioBuffer |
| **Винил** | crackle | 5 сек, ~80 КБ | сразу |
| SFX | шлепок карты, шелест | 0.2–1 сек | спрайт |

> **Винил-крэкл — чит-код.** 80 КБ склеивают разнородные звуки в единую атмосферу и делают любой трек «ламповым». Половина эффекта за копейки.

Эмбиент отдельно от музыки: часть аудитории хочет тишины с дождём, а не битов. Раздельные регуляторы обязательны.

### Граф Web Audio

```
                              ┌─ musicGain ─┐
MediaElementSource(track) ────┤             │
                              └─ lowpass ───┤
AudioBufferSource(rain) ──── ambienceGain ──┼── masterGain ── destination
AudioBufferSource(vinyl) ─── vinylGain ─────┤
AudioBufferSource(sfx) ───── sfxGain ───────┘
```

Три приёма, дающие ощущение полировки:

- **Кроссфейд** за 3 сек до конца, по равной мощности (`cos`/`sin`, не линейно — иначе провал громкости в середине)
- **Приглушение в меню:** не убавлять громкость, а **закрывать lowpass** с 20 кГц до 800 Гц за 300 мс. Звучит как музыка за стеной
- **`visibilitychange`** → мягкий lowpass, не резкая пауза

Все переходы через `setTargetAtTime` / `linearRampToValueAtTime`. Прямое присваивание `gain.value` = щелчок.

**Бесшовный луп:** `loop = true` на MP3 даёт щелчок из-за паддинга кодека. Использовать Opus/WebM либо декодировать в AudioBuffer и зацикливать через `loopStart`/`loopEnd`.

### Станции = настроения всей сцены ⭐

Главная фича, а не просто плеер:

| Станция | LUT | Эмбиент | Частицы |
|---|---|---|---|
| Дождливый вечер | холодный сине-серый | дождь по окну | капли на стекле |
| Свечи | тёплый янтарный | треск камина | угольки |
| Зимнее утро | бледный голубой | ветер | снег |
| Кофейня | нейтральный тёплый | гул, посуда | пар |

Переключение станции меняет **свет на столе, цвет карт, частицы**. LUT интерполируется между двумя текстурами за 2 сек синхронно с кроссфейдом звука.

Станция = пак = SKU. Это то, что невозможно повторить встроенным ютубом.

### UI и мобильные ловушки

- Полоска ~48 px внизу: станция, play/pause, next, громкость. Разворачивается в панель с раздельными слайдерами
- Метафора кассетника или радиошкалы — крутящиеся катушки, стрелка на шкале
- **Media Session API** — название трека на экране блокировки, кнопки на наушниках. 5 строк кода, скачок в ощущении «настоящего приложения»
- ⚠️ **AudioContext только после жеста.** Создавать в обработчике первого касания
- ⚠️ **iOS: переключатель «беззвучно»** глушит Web Audio в Safari. Показывать подсказку
- ⚠️ Радио продолжает играть в фоне (ожидание пользователя), но **игровой цикл останавливать полностью**
- ⚠️ После возврата из фона `AudioContext` часто `suspended` → `resume()` на `visibilitychange`
- Громкости и станцию — в localStorage

**Начать с малого:** винил + один луп дождя + микшер = полдня, 400 КБ, 60% эффекта.

## 8. Бэкенд

```
backend (VPS в РФ):
  /auth/*              OAuth callback, сессии (httpOnly cookie)
  /entitlements        что доступно этому игроку
  /assets/sign         подписанная ссылка на пак (TTL 10 мин)
  /payments/create     создать платёж в ЮKassa
  /payments/webhook    ← ЕДИНСТВЕННЫЙ источник истины по подпискам
  /saves               синхронизация
```

### Схема данных

```sql
users              -- provider, provider_user_id (минимум ПД!)
subscriptions      -- user_id, yk_customer_id, yk_payment_method_id,
                   -- status, current_period_end, trial_end
entitlements       -- user_id, sku, granted_at, source
game_saves         -- user_id, seed, moves[], updated_at   (пара КБ)
webhook_events     -- event_id UNIQUE, processed_at        (дедупликация)
```

### Железные правила

1. **Доступ выдаётся только по вебхуку от ЮKassa.** Никогда по редиректу «оплата прошла» с клиента — там DevTools.
2. **Вебхуки приходят повторно** → дедуплицировать по `event_id`.
3. **Настоящая защита — не флаг `isPremium`, а физическое отсутствие премиум-ассетов в бандле.** Они на сервере, отдаются по подписанной ссылке после проверки в БД.
4. Платёжные данные не хранить никогда — карта у ЮKassa, у вас только `payment_method_id`.

> Честно: скачанный ассет лежит в кеше браузера и его можно достать. Это неизбежно для любой веб-игры. Цель — отсечь массовое расшаривание, а не построить DRM. Не тратить время на обфускацию.

### Офлайн + подписка

Кешировать краткоживущий **JWT-энтайтлмент на 7 дней**. Игрок неделю играет без сети, при каждом онлайн-запуске токен молча обновляется. Отменил подписку — премиум отваливается через неделю.

## 9. Юридика РФ ⚠️

> Не юридическая консультация. Один разговор со специалистом нужен **до** написания серверного кода.

### Блокер №1: юрлицо

Все российские эквайеры требуют РФ-резидентство. Иностранная компания не подключится.

| Вариант | Комментарий |
|---|---|
| **Самозанятый (НПД)** ✅ | Регистрация удалённо через «Мой налог», 6% с поступлений от физлиц, лимит 2.4 млн ₽/год. **ЮKassa поддерживает самозанятых** (в отличие от CloudPayments и Т-Банка). Хватит с запасом на старте. |
| ИП | Больше возможностей, но нужна регистрация по месту жительства в РФ |
| ООО | Избыточно |

⚠️ Комбинация «резидент ЕС + доход из РФ» имеет нюансы с обеих сторон налогообложения.

### Блокер №2: персональные данные (152-ФЗ)

- **Локализация:** ст. 18(5) — запись, накопление и хранение ПД граждан РФ только в базах на территории России. Штраф до 6 млн ₽, повторно — до 18 млн ₽ + блокировка
- **Регистрация в реестре операторов РКН** обязательна. Штраф за отсутствие — до 300 тыс. ₽ (юрлицо) / 50 тыс. ₽ (ИП)
- Нужны: Политика обработки ПДн, согласие на сайте, cookie-баннер

**Решение:** хостинг в РФ. Selectel / Timeweb Cloud / Yandex Cloud / VK Cloud, VPS от ~1000 ₽/мес закроет нагрузки на годы. Postgres или self-hosted Supabase на нём же.

### Инженерный приём: минимизировать ПД

Чем меньше ПД, тем меньше поверхность риска.

Авторизация через **VK ID / Yandex ID (обычный OAuth, не Games)**, хранить только `provider_user_id`. Не имя, не почту, не аватар. Отображаемое имя запрашивать у провайдера на лету, в базу не писать.

Набор входа для РФ-аудитории (Google здесь непопулярен):
- **VK ID** — максимальное покрытие
- **Telegram Login Widget** — минимальное трение
- **Yandex ID** — OAuth
- Email magic link — запасной (почта уже ПД: хеш + отдельно зашифрованное значение)

### 54-ФЗ

Продажа физлицам требует фискального чека. Самозанятые — через «Мой налог», ЮKassa умеет автоматизировать. ИП/ООО — облачная касса как услуга.

### Платежи: детали

- **Способы оплаты — все сразу:** СБП, T-Pay, SberPay, карты Мир/Visa/MC, Mir Pay. Отсутствие СБП заметно режет конверсию в РФ
- **Рекуррент не включается сам** — запрашивать у менеджера ЮKassa через ЛК, заложить время
- **Первый платёж — установочный**, с вводом реквизитов. Обязателен экран с графиком списаний и явное согласие на безакцептное списание. Без этого — чарджбэки
- **СБП для подписок** — появилась привязка счёта (автоплатёж от счёта, а не карты → перевыпуск карты не рвёт подписку). Плюс с 01.01.2026 переводы СБП не подпадают под НДС на платёжные операции, в отличие от эквайринга. Но покрытие банков неполное → карта основной рельс, СБП второй, следить за развитием

## 10. Монетизация

**Подписка на свой сайт в РФ — сложный продукт.** Трение большое (регистрация + карта + доверие незнакомому домену), конкуренты бесплатны. Жёсткая стена на третий день в этом жанре даёт отток, а не конверсию.

**Что работает:**

| Модель | Цена | Комментарий |
|---|---|---|
| **Разовые покупки паков** ⭐ | 149–349 ₽ | Колода / станция+LUT+фон+эмбиент. Купил навсегда. Психологически легче подписки |
| **Lifetime** ⭐ | 990–1490 ₽ | «Всё содержимое навсегда». Для cozy-аудитории часто топ-SKU |
| Подписка | 149–199 ₽/мес | Как опция, не единственный путь |

**Базовая игра бесплатна навсегда.** Платное — контент и удобство: колоды, станции-настроения, фоны, облачная синхронизация, статистика, расклад дня.

Триал — от даты создания аккаунта (не от первого запуска, иначе сбрасывается), **без карты вперёд**. При таких суммах требование карты убьёт больше конверсий, чем принесёт.

Прайс-лист держать **данными, а не константами в коде** — при выходе в Европу поменяются только цифры (PPP: €2–4/мес там vs 149–199 ₽ здесь).

## 12. Дизайн: нерешённое

**10 колонок в портретной ориентации** — главная нерешённая проблема, и она дизайнерская, а не техническая. Варианты: динамическое перекрытие карт, горизонтальный скролл стола, мягкое предложение перевернуть телефон. **Продумать на бумаге до написания рендера.**

**Ощущение (то, что и есть «cozy»):**
- Карта при отпускании чуть проскакивает цель и мягко возвращается — пружина, не линейный твин
- При подъёме тень растёт и размывается
- При драге карта наклоняется по вектору скорости
- Раздача идёт со стаггером, не залпом
- Собранная последовательность улетает с лёгким разлётом

**Ввод:** Pointer Events. Обязательна альтернатива драгу — тап по карте, тап по цели. На маленьком экране это точнее.

## 15. Оживление сцены: слои вместо видео

> Добавлено в ходе работы над первой сценой (`pond`). Раздел отвечает на вопрос «как анимировать фон и что для этого генерировать».

### 15.1 Видео — нет

Ни фоном, ни отдельными элементами.

| | Видео-луп 10 сек | Слои + шейдеры |
|---|---|---|
| Вес | 3–8 МБ | ~400–600 КБ |
| Реакция на игру | нет | пламя подсвечивает поднятую карту |
| Альфа | VP9-alpha без Safari, HEVC-alpha только Safari | нативно |
| Смена настроения (станции) | отдельный файл на каждое | один LUT + параметры |
| Слабый Android | декодер + композитинг | один draw call |

Главное — второй пункт. Видео не может отреагировать на ход игрока, а весь замысел проекта в том, что свет от лампы — общий знаменатель между фоном и картами.

### 15.2 Что чем анимируется

| Элемент | Техника | Стоимость ассета |
|---|---|---|
| Вода | искажение нижнего слоя по тайлящейся normal-map | 512² PNG, генерится кодом |
| Отражения в воде | бесплатно — они уже нарисованы в слое, шейдер их только сдвигает | 0 |
| Листва, цветы | UV-варп по fbm-шуму с маской жёсткости | маска в альфе |
| Пламя лампы | спрайт-лист 12–16 кадров | ~40 КБ |
| Свет от лампы | процедурное гало, форма меняется вместе с `flicker` | 0 |
| Дождь | математика в фрагментном шейдере | 0 |
| Пылинки, светлячки | то же | 0 |
| Котик | отдельный спрайт + кадры моргания и всплытия | ~80 КБ |
| Пар от кружки | частицы / скролл шума | 0 |
| Параллакс | сдвиг слоёв по глубине | 0 |

**Дождь и пыль — не спрайты.** Тысяча капель стоит ровно столько же, сколько одна: всё считается в шейдере, CPU не участвует, аллокаций в кадре нет. Частицы как объекты понадобятся только там, где нужна физика столкновений — то есть нигде в этой сцене.

### 15.3 Единый источник света — главное правило

Всё, что мигает, колышется и меняет цвет, читает значения из `Ambience`. Ни один эффект не заводит собственный таймер.

```
Ambience.flicker ──┬── яркость спрайта пламени
                   ├── форма и радиус гало
                   ├── блик на воде
                   ├── экспозиция кадра
                   └── точечный свет в card.frag   ← ради этого всё и делается
```

Если пламя, гало и блик мигают независимо, сцена рассыпается на набор несвязанных анимаций. Ощущение живого пространства возникает ровно в тот момент, когда игрок поднимает карту и её поверхность дышит вместе с огнём, потому что это физически один и тот же огонь.

### 15.5 Аутпейнт — до нарезки, не после

Исходная картинка 1402×1122 (≈5:4). Игра должна жить на 21:9 десктопе и на 9:19 телефоне, плюс параллаксу нужен запас за краем кадра.

**Сначала расширить всю картинку до ~2560×1600, потом резать.** Наоборот — значит доращивать 13 слоёв по отдельности и ловить расхождение стиля на каждом.

Держать «безопасную зону» в центре: всё сюжетно важное должно попадать в центральные 1402×1122, края — только фон.

### 15.6 Рецепт разбора (ComfyUI, локально)

Порядок обязательно **от переднего плана к заднему**. Иначе одну и ту же дырку придётся восстанавливать по нескольку раз.

```
1. Аутпейнт всей сцены до 2560×1600          Flux Fill / SDXL outpaint
2. Depth Anything V2 -> depth.png            порядок слоёв виден по градиенту
3. SAM 2: клики по объектам -> маски          ~5 минут на всю сцену
4. Цикл, спереди назад:
     вырезать объект по маске -> слой с альфой
     инпейнт дырки -> восстановленный фон     Flux Fill
5. Ручная чистка краёв альфы                  Krita / Photoshop
```

**Что лучше не вырезать, а перегенерировать отдельно:** котик и пламя. Вырезанный из общей картинки котик будет с водой по краям и без нижней половины; перегенерированный на плоском фоне — целый и сразу с кадрами моргания. Стиль держать через IP-Adapter со ссылкой на исходник.

### 15.7 Что генерируется кодом, а что нейросетью

| Ассет | Чем | Почему |
|---|---|---|
| Normal-map воды | **кодом** (`tools/gen_procedural_assets.py`) | нужна идеальная бесшовность; нейросеть тайлящееся не даёт |
| fbm-шум, пылинка, штрих дождя, гало | **кодом** | это математика, а не картинки |
| Маски воды и ветра | **кодом** из полигона + цветового отсева | правится параметром, а не перерисовкой |
| Слои сцены | нейросеть + ручная чистка | |
| Пламя, котик | нейросеть, отдельной генерацией | нужны кадры и чистые края |
| 12 фигурных карт | художник | бутылочное горлышко проекта, см. §14 |

Спектральный метод (случайный спектр с завалом по степенному закону → обратное БПФ) даёт периодичность по построению: текстура бесшовна без единого ручного шва. Анизотропия спектра задаёт вытянутость ряби — для уходящей в перспективу воды волны должны быть длинными по горизонтали.

### 15.10 Ловушки, вскрывшиеся на практике

- **`vite-plugin-glsl` на Vite < 6.3** использует hook-фильтр нового формата, который Rollup 4 игнорирует. Без `@rollup/pluginutils` в зависимостях плагин молча трансформирует **все** файлы проекта, включая `main.ts`, превращая их в строки. Симптом: приложение не стартует, при этом ошибок в консоли нет.
- **Координата для масок в фильтре.** `vTextureCoord` гуляет вместе с паддингом фильтра, сэмплить им маску нельзя. В `layer.vert` заведена отдельная `vLayerUv = aPosition` — ровно 0..1 по области фильтра.
- **Интерполяция станций.** Схема «догоняем цель на долю за кадр» оставляет вечный недобег: значения никогда не приходят в точку. Интерполировать надо от снимка исходных значений к цели по нормированному времени.
- **Ресайз при `resizeTo`.** Слушать `renderer.on('resize')`, а не `window.resize`: Pixi применяет новый размер в своём тике, и обработчик окна прочитал бы `app.screen` до пересчёта.
- **Анизотропия normal-map воды.** Множитель на частоту по оси X *штрафует* эту ось, то есть вытягивает детали *вдоль* неё. Легко перепутать знак и получить рябь, бегущую вертикальными полосами.

## 16. Логика и карты

> Добавлено после §15. Шаги [1] и [3] из §11 закрыты: игра играется.

### 16.1 core/ — чистая логика

Ноль импортов DOM, Pixi и сети. 40 тестов на Vitest.

```
core/rng.ts     mulberry32 + Фишер–Йетс + сид расклада дня
core/types.ts   Card, GameState, Move, GameEvent
core/rules.ts   createDeal, movableRunLength, canPlace, isLegal,
                getLegalMoves, applyMove, isWon, isStuck
core/game.ts    Game: история ходов, отмена, сохранение
```

**Отмена сделана реплеем, а не обратными командами.** Обратные команды
пришлось бы писать для каждого побочного эффекта — переворота карты,
снятия последовательности, счёта, — и каждый стал бы отдельным источником
рассинхрона. Реплей двухсот ходов занимает доли миллисекунды и по
построению не может разойтись с прямым ходом.

Побочная выгода — формат сохранения:

```ts
{ seed: 20260818, suits: 1, moves: [{t:'move',from:0,to:8,count:1}, {t:'deal'}] }
```

Сотня ходов укладывается в ~4 КБ. Это же и есть `game_saves` из §8, и это
же — ссылка «сыграй мой расклад».

### 16.2 Граница логики и рендера

`applyMove` возвращает список семантических событий:

```
cardsMoved | cardFlipped | dealt | runCompleted | won
```

Состояние меняется мгновенно, рендер превращает события в таймлайны.
Ветки «а вдруг ход не пройдёт» в анимациях не существует — к моменту
анимации логика уже досчитала всё до конца.

### 16.3 Композитная колода

Атлас собирается процедурно в один `RenderTexture`, сетка 9×6 = 54 ячейки
(52 лица + рубашка + пустое место), зазор 2 px между ячейками.

| Что | Как |
|---|---|
| Масти | четыре SVG-пути, вектор |
| Числовые карты 2–10 | рамка + пипсы по таблице раскладок |
| Тузы | крупный знак масти |
| **Фигурные В/Д/К** | **заглушка: рамка + глиф** |
| Рубашка | ромбовидная сетка под маской + эмблема |

Заменить заглушку фигурных карт = переписать тело `drawFigure`. Атлас,
раскладка и рендер не трогаются. Это те самые 12 иллюстраций из §14.

Атлас пересобирается при изменении ширины карты больше чем на 25% —
растянутая с 60 px на 160 px карта даёт мыло на подписях рангов.

### 16.4 Ощущение

| Приём | Где |
|---|---|
| Пружинный возврат с проскоком | `easing.outBack` |
| Тень растёт, размывается и отъезжает при подъёме | `CardView.setLift` |
| Наклон по вектору скорости, затухающий вниз по стопке | `CardView.setTilt` |
| Раздача стаггером по 45 мс | `CardTable.applyEvents` |
| Собранная последовательность улетает с разлётом | `CardTable.flyOutRun` |

Твинер свой, а не GSAP. Готовые библиотеки крутят собственный
`requestAnimationFrame`; здесь анимации обязаны идти от тикера сцены —
чтобы замирать вместе с игровым циклом при уходе вкладки в фон (§7),
подчиняться тирам качества и работать в headless-проверке.

### 16.5 Карты внутри сцены, а не поверх

`world` содержит И фон, И карты. Атмосферный проход висит на нём, поэтому
гало лампы, мерцание пламени, дождь и виньетка ложатся и на карты — без
единой дополнительной строки. Это и есть связка «один огонь на всю
сцену» (§15.3), полученная бесплатно правильной иерархией.

HUD остаётся DOM-оверлеем снаружи: на цифрах счётчика зерно и виньетка
читались бы как грязь, а не как атмосфера.

### 16.6 Раскладка

Динамическое перекрытие: шаг между картами считается по **самой длинной
колонке сейчас**, а не по теоретическому худшему случаю. Иначе на старте
карты слиплись бы в комок ради ситуации, которая наступит через полсотни
ходов.

Верх отдан HUD, низ — лотку с запасом и собранными последовательностями.
Колонки живут строго между ними.

**Портретная ориентация по-прежнему не решена (§12).** Стоит нижняя
граница ширины карты 44 px, ниже которой стол упирается. При ширине
экрана ~375 px десять колонок дают ~33 px на карту — ранги не читаются.
Это честный предел, а не решение; дизайн-решение всё ещё нужно.

### 16.7 Ввод

Pointer Events. Драг и обязательная альтернатива — тап по карте, тап по
цели (§12): на маленьком экране это точнее.

Карты **не** делаются интерактивными объектами. Попадание считается
вручную по раскладке в `hitCard()`: 104 интерактивных объекта — это
лишние обходы дерева на каждое движение указателя, ради задачи, которая
решается двумя делениями.

### 16.8 Ловушки, вскрывшиеся на практике

- **Вложенный `GraphicsPath.addPath`.** Трансформация внешнего `addPath`
  не доходит до инструкций пути, который сам состоит из `addPath`.
  Фигура молча выпадает в исходном масштабе. Матрицу навешивать на каждый
  примитив по отдельности и ровно один раз.
- **Разворот глифа отрицательным масштабом.** При якоре в углу глиф
  разворачивается ОТ точки привязки и уезжает за пределы карты. Нужен
  якорь по центру и `rotation = π`.
- **Зазор между ячейками атласа.** Без него билинейная фильтрация на краю
  спрайта подмешивает соседнюю карту, и по периметру идёт цветная кайма.
- **Твин, переживший свою цель.** После пересборки сцены анимация на
  уничтоженном объекте пишет в мёртвый `Transform` и роняет весь игровой
  цикл. Снимать анимации до `destroy`, а не после. Твины на карте висят на
  двух разных объектах (`root` и `face.skew`) — снаружи одним `kill` их не
  убрать.
- **Vitest 4 требует Node 20.12+** (`node:util` → `styleText`). На Node 18
  ставить Vitest 2.

### 17.2 Акторы

Слой занимает холст целиком, актор — стоит в конкретной точке. Координаты

```json
{ "id": "flame", "type": "flame", "anchor": [1916, 1090], "size": [44, 52],
  "parallax": 0.28, "grid": [4, 4], "fps": 12 }
```

**Пламя** — единственное место во всей сцене, где кадровая анимация
оправдана: язычок огня меняет форму нелинейно, и математика не даст того
же за сравнимые деньги. Складывается аддитивно: это свет, а не наклейка.
Яркость берётся из общего `flicker`, тем же значением дышат гало, блик на
воде и экспозиция кадра.

**Котик** — две картинки и ноль кадров анимации:

| Что видит игрок | Чем сделано |
|---|---|
| Моргание | подмена текстуры на 90 мс |
| Всплытие | сдвиг неподвижного спрайта за линию обреза |
| Кромка воды | маска с волнистым краем, ползущая вбок |
| Отражение | зеркальная копия ниже ватерлинии, alpha 0.24 |
| Качка | синус малой амплитуды |

Отражение добавлено не для красоты: без него котик читается наклейкой.
Глаз ищет ответ воды на предмет и, не находя, отказывается верить, что
предмет в воде.

### 17.3 Что пришлось поправить после подключения

- **Позиция лампы.** В манифесте она была задана для исходного кадра
  1402×1122. После аутпейнта холст стал 2560×1600, и гало светило мимо
  лампы. Позиция актора и позиция источника света — одна и та же точка,
  задавать её дважды нельзя.
- **Плотность подложки.** Значения, разумные для яркого плейсхолдера, на
  ночном пруду складываются с ним и дают кашу. Подложка обязана отделять
  карты от фона, а не гасить фон.
- **Вес колоды.** Мастера 1024px публиковались как есть — 22 МБ ради
  окошек, которые рисуются шириной около сотни пикселей. `wire_deck.py`
  теперь уменьшает при публикации, мастера остаются в `art/`. Экономия
  16 МБ из 22.

### 17.4 Ловушка, стоившая получаса

**`renderer.extract` снимает по границам сцены, а не по вьюпорту.**

Границы выходят за экран на запас под параллакс, поэтому в снимок попадает
область, которой игрок не видит. По краям кадра появлялись тёмные полосы,
которых на экране нет, и полчаса ушло на поиск бага в композитинге,
которого не было.

Для проверки внешнего вида снимать нужно **сам канвас**.

Это общий случай частой ошибки: инструмент проверки соврал, и время ушло
на исправление отчёта, а не системы. Прежде чем чинить странность, стоит
проверить, что её вообще кто-то видит, кроме измерителя.

### 17.5 Прочие мелочи, вскрывшиеся на практике

- **`sprite.height` стирает знак `scale.y`.** Сеттер пересчитывает масштаб
  из размера текстуры, и зеркальное отражение молча перестаёт быть
  зеркальным. Знак ставить после размера.
- **Полигон-маска с самопересечением** триангулируется в кашу. Направление
  обхода контура — не стилистика, а условие работоспособности.
- **Маску ветра рисуют в сером, а шейдер читает альфу.** Требовать RGBA от
  художника значит требовать лишний шаг ради ничего: перекладку взял на
  себя `wire`.

### 18.2 Кайма вместо подгонки

Слои приехали с растушёванной каймой в 45 пикселей за контуром объекта.
Сумма альф по холсту — 2.51, то есть слои намеренно перекрываются.

Это решает проблему, которую иначе пришлось бы ловить руками. При сдвиге
камеры на 120 px расхождение между стеклом лампы (параллакс 0.34) и небом
(0.00) составляет 41 пиксель: без запаса между слоями открылись бы чёрные
щели ровно по контурам вырезанных объектов.

Проверено: на всех крайних положениях камеры в кадре не больше одного
чёрного пикселя.

**Кайму при подключении не обрезать.** Выглядит как лишние данные, а на
деле это единственное, что держит сцену собранной в движении.

### 18.3 Глубина актора — не его параллакс

С двенадцатью слоями всплыла ошибка, которой на трёх не было: акторы
клались поверх всей сцены. Пламя горело перед стеклом лампы, котик плавал
поверх стола.

Одним параллаксом это не выражается. Пламя едет **вместе** с лампой
(0.34), но обязано быть **под** стеклом. Котик едет с водой (0.16), но
должен оказаться над кувшинками и под цветами переднего плана.

Поэтому у актора два независимых поля:

```json
{ "id": "flame", "parallax": 0.34, "after": "11-lantern" }
{ "id": "cat",   "parallax": 0.16, "after": "06-lilypads" }
```

`parallax` — скорость, `after` — место в стопке.

### 18.4 WebP: 71 МБ -> 6.9 МБ

Двенадцать слоёв 2560×1600 RGBA в PNG весили 58 МБ. PNG хранит все
пиксели, даже когда слой прозрачен на 99% — у стекла лампы покрытие 1.2%,
а файл всё равно пятимегабайтный.

| | PNG | WebP q95 | |
|---|---|---|---|
| Слой фона | 4.76 МБ | 0.41 МБ | **11.7×** |
| Ошибка цвета | — | 1.0 / 255 | не видно на живописи |
| Ошибка альфы | — | **0** | ни одного бита |

Альфа сохраняется без потерь принудительно (`alpha_quality=100`), и это не
перестраховка: помятая альфа вернула бы щели из §18.2. Здесь альфа — не
прозрачность в декоративном смысле, а геометрия слоя.

Это тот же принцип, что в ⚠️1 из §6 про нормали, но применённый по факту, а
не по типу файла: сжимать с потерями можно то, что глаз воспринимает как
цвет, и нельзя то, что участвует в расчётах.

### 18.5 У Flux не работает негативный промпт

В задании на генерацию был указан негатив `text, letters, playing card`.

Flux дистиллирован по guidance и идёт на CFG 1 — отрицания игнорируются
полностью. Не «работают слабо», а не работают.

Что вместо этого: позитивное описание нужного, замер занятости углов
скриптом и вычистка подписей штампом. Учитывать при генерации остальных
30 лиц.

### 18.6 Что осталось

1. **30 лиц карт** — черви, бубны, трефы, ранги 1..10. Фигурные у них есть,
   но горизонтальные 1024×832: им срезает бока, стоит перегенерировать
2. **Маски ветра пройти кистью** — автомат не отличает ствол от листвы

3. **Звук** — винил, дождь, микшер (§7). Полдня, 60% эффекта

## 19. Кассетник на столе

Первый интерактивный предмет сцены. Раньше игрок мог трогать только карты.

### 19.1 Предмет, а не панель

Кнопки транспорта нарисованы на корпусе и стоят на доске рядом с кружкой.
Не в HUD.

Разница не косметическая. Вынесенный наверх плеер — это панель управления
поверх картины: он живёт в другом пространстве, не получает света от лампы,
не едет с параллаксом и всё время напоминает, что перед тобой программа.
Кассетник на столе — часть той же сцены, что и пруд.

Цена: пришлось решать, как он вообще получает клики (§19.2).

### 19.2 Ввод: картинка внизу, зона нажатия наверху

Стол пасьянса перекрывает **весь экран** своей областью попадания — иначе
не отработать перетаскивание карты в произвольную точку. Предмет, лежащий
в сцене под столом, не получил бы ни одного клика.

Решение — развести отрисовку и ввод:

```
world
├── scene.root     ← корпус магнитофона стоит здесь, между слоями
├── table.root     ← перекрывает всё
└── scene.input    ← невидимые зоны нажатия, поверх стола
```

Актор отдаёт наружу два контейнера: `root` уезжает в стопку слоёв,
`input` — в отдельный слой сверху. Зоны позиционируются в тех же
экранных координатах, что и клавиши, и крупнее их на четверть: на
телефоне палец толще клавиши.

### 19.3 Раскладка корпуса — данные, а не константы

Код рисует поверх картинки катушки, индикатор и подпись, а клавишам даёт
отклик на нажатие. Чтобы знать, куда это класть, он берёт координаты из
манифеста в долях спрайта:

```json
{
  "window": [0.342, 0.183, 0.444, 0.300],
  "keys": [[0.344, 0.673, 0.115, 0.228],
           [0.477, 0.665, 0.193, 0.220],
           [0.682, 0.658, 0.146, 0.212]]
}
```

Клавиши разной ширины — корпус развёрнут в три четверти, это перспектива.
Захардкоженная сетка «три равные кнопки по центру» такого не выразила бы,
и художнику пришлось бы рисовать корпус под код вместо обратного.

### 19.4 Что рисует код, а что художник

| Код | Художник |
|---|---|
| Катушки, крутятся только при воспроизведении | Корпус, окно, клавиши |
| Индикатор — дышит вместе с пламенем лампы | Тень под корпусом |
| Подпись под окном | Потёртости, свет справа |
| Просадка клавиши при нажатии | |

Катушки и индикатор нарисованными быть не могут: неподвижная катушка
сообщает, что ничего не играет, а ровный светодиод выдаёт электричество
там, где вся сцена держится на керосине.

### 19.5 Точка подключения плеера

```js
stage.radio.onCommand = (cmd) => { /* 'prev' | 'toggle' | 'next' */ }
stage.radio.playing = true
stage.radio.setLabel('название трека')
```

Актор звука не касается вообще. Он про кнопки.

### 19.6 Flux отказался убирать блокнот

Блокнот со стола стирали инпейнтом четыре раза: по контуру, по
прямоугольнику, в отдельном кадре без контекста и с черновой заливкой на
denoise 0.5. Каждый раз модель рисовала **новую книгу**.

Контекст «кружка на столе, доски, тёплый свет» перевешивает промпт, а
негативы у Flux не работают (§18.5) — сказать «книги не надо» нечем.

Сделано без модели: каждая строка дырки заполнена доской, взятой на 170 px
**ниже**. Вертикальный сдвиг сохраняет и направление волокон, и градиент
света по строке. Горизонтальный не годится — слева от блокнота уже не
стол, а куст.

Вывод на будущее: когда инпейнт упирается в собственный здравый смысл
модели, дешевле взять пиксели оттуда, где нужная фактура уже есть, чем
уговаривать сеть.
