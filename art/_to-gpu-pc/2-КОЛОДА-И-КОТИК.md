# Колода и котик — что генерировать

Два задания, независимых от нарезки сцены. Делаются на той же машине с
GPU, в том же ComfyUI.

---

## Часть 1. Колода

### Главное: генерируется только картинка внутри окошка

На референсе кажется, что карта нарисована целиком. Это не так — и не
должно быть так.

```
┌──────────────┐
│ K            │  ← индекс: рисует КОД
│ ♠            │
│  ┌────────┐  │
│  │        │  │  ← это генерирует нейросеть
│  │  арт   │  │     1024x832, соотношение 1.23
│  │        │  │
│  └────────┘  │
│            ♠ │  ← рамка, второй индекс: рисует КОД
│            K │
└──────────────┘
```

Почему так, а не карта целиком:

- **Текст.** Диффузионные модели не умеют надёжно рисовать буквы. «K♠» на
  сгенерированной карте будет мусором, который придётся замазывать.
- **Согласованность.** Двенадцать независимо сгенерированных карт разъедутся
  по толщине рамки, положению индекса и оттенку бумаги. Код рисует всё это
  одинаково по определению.
- **Локали.** Русская колода это В/Д/К/Т вместо J/Q/K/A (§6). Один и тот же
  арт работает под обе, если буквы не вшиты в картинку.
- **Вес.** Двенадцать окошек вместо пятидесяти двух полных карт.

### Что рисовать в окошке

На референсе внутри карт — **маленькие пейзажи**: горы, домик, мельница.
Не геральдические фигуры. Это и проще генерировать, и лучше ложится на
«уют», ради которого всё затевается.

Двенадцать сюжетов, по три на масть. Разумно связать масть с настроением:

| Масть | Настроение | Примерные сюжеты |
|---|---|---|
| ♠ пики | ночь, дождь | пруд под дождём, фонарь у воды, силуэт леса |
| ♥ червы | тёплый вечер | окно с лампой, костёр, чайник на столе |
| ♦ бубны | утро | туман над полем, мостик, цветущий склон |
| ♣ трефы | лес | тропа, старое дерево, папоротник |

Это предложение, не требование. Важно другое: **все двенадцать в одном
стиле и в одной палитре.**

### Как держать стиль

Стиль тянуть с самой сцены пруда через IP-Adapter — тогда карты не будут
выглядеть чужими на этом столе.

Генерировать **пачкой в один заход**, а не по одной в разные дни: между
сессиями уплывают seed, веса и настроение, и это видно.

Промпт-шаблон один, меняется только сюжет:

```
<сюжет>, studio ghibli style, soft painterly, muted teal and warm amber
palette, gentle rim light, no text, no letters, no borders, no frame
```

Негатив обязательно включает `text, letters, watermark, border, frame` —
иначе модель дорисует свою рамку внутрь окошка, и получится рамка в рамке.

### Размеры

| Что | Размер | Соотношение |
|---|---|---|
| `figures/*.png` | **1024×832** | 1.23 |
| `back.png` | **768×1114** | 0.69 |

Соотношение важнее абсолютного размера: картинка с другими пропорциями
растянется по окошку, и это читается как брак печати. `wire_deck.py`
проверяет и не пускает.

### Рубашка

Одна картинка на всё поле рубашки. Код положит её на бумажную подложку со
скруглением — про углы думать не надо.

Что хорошо работает: плотный орнамент без явного центра, либо симметричный
рисунок. Рубашка видна стопкой из сорока карт, поэтому крупный сюжет там
превращается в кашу.

### Подключение

```
art/deck/figures/S11.png   валет пик      S пики, H червы, D бубны, C трефы
art/deck/figures/S12.png   дама пик       11 валет, 12 дама, 13 король
art/deck/figures/S13.png   король пик
art/deck/back.png          рубашка
```

```bash
python tools/wire_deck.py --check
python tools/wire_deck.py
```

Класть можно по одной. Карты без картинки остаются на процедурных
заглушках, игра работает.

## Часть 2. Котик

### Кадры анимации генерировать НЕ надо

Соблазн понятный: котик моргает и всплывает, значит нужна раскадровка.
На деле раскадровка — худший из возможных путей.

Диффузионная модель не держит персонажа между кадрами: у котика поедет
форма ушей, размер зрачков, оттенок шерсти. Восемь кадров всплытия
превратятся в восемь слегка разных котов, и это будет заметно именно
потому, что они идут подряд.

**Всё движение делается кодом. От нейросети нужны две картинки.**

### Что генерировать

| Файл | Что | Размер |
|---|---|---|
| `cat-open.png` | котик, глаза открыты, прозрачный фон | ~512×512 |
| `cat-blink.png` | **то же самое**, но глаза закрыты | ~512×512 |

Второй файл — не отдельная генерация. Это первый файл, у которого
**заинпейнчена только область глаз**. Всё остальное обязано остаться
пиксель в пиксель: маска инпейнта покрывает только глаза.

Рисовать котика **целиком** — с шеей и грудью, уходящими вниз за нижний
край кадра. Не по ватерлинию: код сам решает, сколько его торчит из воды.

### Как получается движение

| Что видно игроку | Чем сделано |
|---|---|
| Моргание | подмена текстуры на 90 мс по таймеру со случайной паузой |
| Всплытие и погружение | вертикальный сдвиг спрайта под маской ватерлинии |
| Круги по воде | те же расходящиеся кольца, что уже есть в шейдере воды |
| Покачивание | синус малой амплитуды |

Всплытие — это не анимация персонажа. Это перемещение неподвижной
картинки вверх за линию, ниже которой она обрезана. Ровно так это
выглядит и в жизни.

Ушами можно дёргать, если вырезать их отдельными спрайтами и вращать —
но это уже полировка, не первый заход.

### Куда класть

```
art/scene/pond/cat/cat-open.png
art/scene/pond/cat/cat-blink.png
```

Код для котика напишу, когда появятся эти две картинки: ему нужно знать
реальные пропорции спрайта и где у него ватерлиния.

---

## Порядок

1. **Три слоя сцены** — без них не видно, работает ли подход вообще
2. **Рубашка** — она видна всегда, в каждой партии, с первой секунды
3. **Двенадцать окошек** — самая долгая часть, зато нарезается на подходы
4. **Котик** — две картинки, чистый шарм

Рубашка раньше фигурных карт не по красоте, а по частоте: закрытых карт на
столе больше, чем фигурных, и видны они с первого кадра.
